Transverse · Pipeline — Leçon 11 / ~18

SAST / DAST / SCA / IaC-scan : qui trouve quoi

Ta pipeline empile quatre familles d'analyse de sécurité. Le jury va vouloir t'entendre les distinguer : chacune voit ce que les autres ne voient pas. Voici la carte.

Le seul point à retenir Aucun outil ne voit tout. On combine quatre angles : ton code (SAST), tes dépendances (SCA), ton infrastructure déclarée (IaC-scan) et ton application qui tourne (DAST). C'est de la défense en profondeur appliquée à la chaîne de fabrication : chaque famille rattrape les angles morts des autres.

2. L'axe qui structure tout : statique vs dynamique

La grande ligne de partage, celle que le jury attend :

  • Statique (SAST, SCA, IaC) — on lit sans exécuter. Tôt dans le cycle, rapide, exhaustif sur ce qu'on lit. Mais aveugle au comportement réel (faux positifs : du code « dangereux » jamais atteint).
  • Dynamique (DAST) — on exécute et on attaque comme un vrai attaquant (boîte noire). Voit le comportement réel, peu de faux positifs. Mais plus tard (il faut une app déployée) et ne voit que ce qui est exposé.
La métaphore qui marche à l'oral SAST/SCA/IaC = relire les plans du bâtiment avant de construire. DAST = essayer d'ouvrir les portes une fois le bâtiment debout. Les deux sont nécessaires : un plan correct mal réalisé, ou une porte oubliée, n'apparaît qu'au test réel.

3. La carte appliquée à ta pipeline

Ton .github/workflows/ci.yml couvre les quatre familles. Mets un nom de catégorie sur chaque étape — c'est exactement ce que le jury veut t'entendre faire :

iac-lint :  tflint + Checkov   → IaC-scan   (l'infra Terraform)
sast     :  Semgrep            → SAST       (le code Go)
image    :  Trivy              → SCA        (les images / CVE)
(exposé) :  ZAP baseline       → DAST       (l'app qui tourne)

Et l'ordre n'est pas un hasard — c'est le principe du « shift-left » :

Shift-left Déplacer la sécurité le plus tôt possible dans le cycle. Les analyses statiques (qui ne demandent rien d'exécuté) passent en premier : si ton code ou ton infra a une faille évidente, on casse le build avant même de construire l'image ou de déployer. Plus un défaut est trouvé tôt, moins il coûte cher à corriger.

4. Pourquoi « bloquant » et pas « avertissement »

Détail crucial de ta pipeline : ces étapes cassent le build (exit-code ≠ 0), elles n'émettent pas un simple warning. C'est volontaire — le commentaire en tête de ton ci.yml le dit : « c'est une porte de qualité, pas un avertissement ».

La logique : un avertissement qu'on peut ignorer sera ignoré (« on corrigera plus tard »). Une quality gate bloquante force la décision maintenant : soit on corrige, soit on accepte explicitement le risque (ex. nosemgrep, ignore-unfixed). La sécurité devient une condition de livraison, pas une option.

Question de jury

« Vous avez du SAST et du SCA. Pourquoi en plus du DAST ? N'est-ce pas redondant — ils cherchent tous des vulnérabilités ? »

Réponse : non, ils regardent des choses disjointes. Le SAST lit mon code (une injection que j'aurais écrite). Le SCA regarde le code que je n'ai pas écrit — mes dépendances et l'image de base — pour les CVE connues. Le DAST, lui, ignore le code : il attaque l'application qui tourne et voit ce qu'un attaquant verrait réellement, y compris des défauts de configuration ou des interactions que l'analyse statique ne peut pas déduire. Un exemple : un header de sécurité manquant n'apparaît ni dans le code source ni dans les dépendances — seul le DAST, qui interroge l'app réelle, le détecte. C'est de la défense en profondeur : chaque famille couvre l'angle mort des autres.

Vérifie que ça tient

Quelle est la différence fondamentale entre SAST et DAST ?
SAST = statique = lit le code source sans l'exécuter (tôt, exhaustif, des faux positifs). DAST = dynamique = exécute et attaque l'app comme un vrai attaquant (plus tard, comportement réel, peu de faux positifs). Relire les plans vs essayer d'ouvrir les portes.
Dans ta pipeline, à quelle famille appartient Trivy, et que regarde-t-il ?
Trivy = SCA (Software Composition Analysis) : il scanne les images conteneur et leurs dépendances pour des CVE connues, et casse le build sur HIGH/CRITICAL. Dans ta pipeline : Semgrep=SAST, Checkov=IaC-scan, ZAP=DAST, Trivy=SCA.
